# แผนปรับเว็บลุ่มน้ำป่าพะยอมตามบันทึกประชุม

จัดทำวันที่ 10 ตุลาคม 2569 จากเอกสาร `แก้ไขweb-วช-ป่าพะยอม22-9-69 (1).docx` ซึ่งมีบันทึกประชุมวันที่ 18 และ 19 กันยายน 2569 พร้อมภาพประกอบ 30 ภาพ เทียบกับซอร์สโค้ดใน repository ณ วันที่จัดทำ

ควรเริ่มจากความถูกต้องของข้อมูล ขอบเขตลุ่มน้ำ และเกณฑ์เตือนภัย แล้วจึงปรับหน้าแรก เชื่อมแบบจำลอง และต่อยอดงานอพยพ แผนนี้ยังไม่ได้แก้โค้ดแอป ไม่ได้ตรวจข้อมูลจริงในฐานข้อมูล และยังไม่ยืนยันความถูกต้องของ API ภายนอกในสภาพใช้งานจริง

## สิ่งที่พบในเว็บปัจจุบัน

ตำแหน่งไฟล์ component ในตารางอยู่ใต้ `src/components/` และ `src/components/dashboard/views/` ตามชื่อไฟล์

## ข้อกำหนดจากเอกสารและงานที่ต้องทำ

P0 = ความถูกต้องที่ควรแก้ก่อน, P1 = ขอบเขตหลักตามเอกสาร, P2 = งานต่อยอดที่ต้องรอข้อมูลหรือข้อสรุป

| รหัส | ข้อกำหนด | แผนปรับ | ลำดับและเงื่อนไข |
| --- | --- | --- | --- |
| R01 | สรุปแหล่งข้อมูลแต่ละหน้า และ recheck ข้อมูลจากเป้ | ทำบัญชีแหล่งข้อมูล ระบุเจ้าของ URL/ชุดข้อมูล หน่วย ขอบเขต เวลาตรวจวัด เวลาอัปเดต วิธีคำนวณ และข้อจำกัด พร้อมแสดงที่มาบนหน้า | P0 ขอชุดล่าสุดจากเป้ |
| R02 | ฝนสูงสุดต้องเป็นลุ่มน้ำป่าพะยอมและมีชื่อสถานี | กรองสถานีที่อยู่ในขอบเขตที่รับรอง แล้วหาสูงสุดแยก 24/72 ชั่วโมง แสดงชื่อ รหัส เวลา และจำนวนสถานีที่มีข้อมูลใช้ได้ | P0 รอขอบเขต/บัญชีสถานี; แค่เปลี่ยนคำว่าจังหวัดไม่เพียงพอ |
| R03 | ตรวจระดับน้ำและสถานะวิกฤต | ตรวจหน่วย ม./ม.รทก. ระดับอ้างอิง คุณภาพข้อมูล และความหมายรหัสสถานะ เก็บที่มาเกณฑ์ ไม่จัดข้อมูลที่หายเป็นปกติ | P0 ขอเกณฑ์จากเจ้าของข้อมูล |
| R04 | ตัดบางพื้นที่/สถานีที่อยู่นอกขอบเขต | ทำรายการเสนอคงไว้/ไม่รวม พร้อมเหตุผล ใช้ขอบเขตลุ่มน้ำจริง และแยกจุดต้นน้ำ/สถานีอ้างอิงนอกพื้นที่ถ้ามีเหตุผลทางอุทกวิทยา | P0 ต้องรับรองรายการ ไม่ลบจากชื่ออำเภออย่างเดียว |
| R05 | หน้าแรกใช้สถานีสามกลุ่ม | รวมจุดติดตั้ง อ.หญิง/มวล. โทรมาตรใหญ่ และโทรมาตรเล็ก แสดงเขียวห้าเหลี่ยม แดงวงกลม เหลืองสามเหลี่ยมตามภาพแผนที่ | P1 รอทะเบียนและพิกัดที่รับรอง |
| R06 | เพิ่มสถานีและโครงข่ายน้ำใต้คาดการณ์ | เพิ่มหน้ารายการสถานี กราฟประวัติ สถานะล่าสุด และความสัมพันธ์ต้นน้ำ–ปลายน้ำ อ้างอิงภาพตัวอย่างในเอกสาร | P1 ต่อจาก R04–R05 |
| R07 | ปรับหน้าแรก แผนที่ซ้ายเต็มพื้นที่ เรดาร์ลงล่าง ENSO ขวา | คงส่วนอื่นที่เอกสารระบุว่าถูกแล้ว ปรับสัดส่วนแผนที่ ย้ายเรดาร์ เพิ่ม ENSO พร้อมแหล่งข้อมูลและรอบรายงาน มือถือเรียงเนื้อหาให้อ่านได้ | P1 ENSO รอเป้ |
| R08 | เพิ่ม SOP | เพิ่มพื้นที่อ่าน SOP ตามสถานการณ์ ระดับเตือน ขั้นตอน ผู้รับผิดชอบ ช่องทางติดต่อ เวอร์ชัน และวันทบทวน เชื่อมจากประกาศและศูนย์อพยพ | P1 รอ SOP ทางการ; ไม่แต่งขั้นตอนแทนหน่วยงาน |
| R09 | เปลี่ยน layer แล้วจุดต้องไม่หาย | แยกชั้นสถานีออกจากชั้นพื้นที่ กำหนดลำดับซ้อน/การรับคลิก และตัวเปิดปิดจริง คงสถานีจนผู้ใช้ปิดเอง | P1 ทดสอบทุกคู่ layer หลัก |
| R10 | เพิ่ม SPI/SPEI และข้อมูลภัยแล้ง | เพิ่ม adapter และมุมมองดัชนี ระบุช่วงเวลา พื้นที่อ้างอิง เกณฑ์ และวันที่ข้อมูล เอกสารตอนต้นเขียน SEI แต่ช่วงหลังเขียน SPI/SPEI จึงต้องยืนยันชื่อกับเป้ | P1 รอข้อมูลและคำอธิบายแบบจำลอง |
| R11 | เพิ่มฝนคาดการณ์รายลุ่มน้ำและรายจุด | รับ code/model จากเป้ แยกผลคาดการณ์ออกจากค่าตรวจวัด แสดงรอบที่ออกผล ช่วงเวลาที่คาดการณ์ พื้นที่ และข้อจำกัดของผล | P1 รอ code, ตัวอย่างผล และวิธีรัน |
| R12 | วิเคราะห์สถิติ เช่น ฝนสูงสุด 7 วัน จากฐานข้อมูลเรา | เก็บประวัติของสถานีที่ใช้งาน ทำงานดึงข้อมูลเบื้องหลัง และคำนวณรายสถานีโดยนิยามช่วงเวลา/ความครบถ้วนให้ชัด ก่อนสรุปสูงสุดทั้งลุ่มน้ำ | P1 ต้องมีประวัติครบ หรือระบุช่วงที่ข้อมูลไม่ครบ |
| R13 | เก็บข้อมูลถี่ขึ้นเมื่อฝนเพิ่ม | เพิ่มนโยบายความถี่ตามเกณฑ์ พร้อมเวลารักษาความถี่และกลับสู่ปกติ ป้องกันข้อมูลซ้ำและตรวจช่องว่าง | P1 การ poll ถี่ไม่ทำให้ต้นทางวัดถี่ขึ้น; webhook ต้องประสานอุปกรณ์หากต้องเปลี่ยนรอบส่ง |
| R14 | เอาประกาศข่าวออกมาด้านนอก | ย้ายจากคลังข้อมูลเป็นเมนูหลัก แยกสิทธิ์อ่าน/จัดการ เผยแพร่เฉพาะประกาศที่ผ่านขั้นตอนยืนยันตามระบบ | P1 ใช้หน้าประชาชนที่มีอยู่ต่อได้ |
| R15 | ใช้ข้อมูล ปภ. จากจันที่มีความเสี่ยงและผู้ใช้ประโยชน์ | รับชุดข้อมูลจริง จับคู่หมู่บ้าน/พื้นที่ ตรวจช่วงเวลาและนิยามผู้ใช้ประโยชน์ แยกจากผู้ได้รับผลกระทบและยอดผู้เข้าเว็บ | P1 รอจัน และตกลงฟิลด์ที่เผยแพร่ได้ |

| R17 | แสดงหน้าในแต่ละหัวข้อ | เสนอ URL สำหรับแต่ละเมนู เปิดลิงก์ตรง รีเฟรช และย้อนกลับได้ เพราะปัจจุบันเจ้าหน้าที่เลือกหน้าด้วย state | P1 เป็นการตีความข้อความที่ยังไม่ชัด ต้องยืนยันว่าหมายถึง URL แยกหรือ drill-down |

## ข้อมูลที่ต้องขอและประเด็นที่ต้องสรุป

| ผู้ประสานงาน/แหล่ง | สิ่งที่ต้องได้ | งานที่เกี่ยวข้อง |
| --- | --- | --- |
| เป้ | ชุดข้อมูลล่าสุด code ฝนรายลุ่มน้ำ/รายจุด ENSO SPI/SPEI คำอธิบาย SEI แบบจำลองเวลาน้ำเดินทาง ตัวอย่างผลและวิธีรัน | R01–R03, R07, R10–R11, R20 |
| อ.หญิง/มวล. และเจ้าของโทรมาตร | ทะเบียนสถานีทั้งสามกลุ่ม รหัส พิกัด ระบบพิกัด หน่วยงาน เจ้าของ API ประเภทเครื่องมือ และสถานีที่ให้คงไว้ | R04–R06 |

ลิงก์ตัวอย่าง `https://utaphao-water-command.dpakorn75.chatgpt.site/#network` เปิดผ่านเครื่องมือเว็บไม่ได้ในการตรวจครั้งนี้ จึงใช้ภาพตัวอย่างที่ฝังในเอกสารเป็นข้อมูลประกอบ ยังไม่ได้ยืนยันพฤติกรรมของหน้าอ้างอิงจริง

## ลำดับการดำเนินงาน

### รอบที่ 1 ตรวจและทำข้อมูลหลักให้เชื่อถือได้

ขอบเขต R01–R04 และข้อมูลตัวอย่างที่พบในหน้าแรก/แผนที่ ทำบัญชีแหล่งข้อมูล ตกลงขอบเขต สถานี หน่วย และเกณฑ์สถานะ เตรียมสถานะไม่มีข้อมูล/ข้อมูลเก่าแทนตัวเลขตัวอย่าง

ไฟล์หลัก: `src/lib/situation/adapters.ts`, `src/lib/dashboard-data.ts`, `src/components/dashboard/views/DashboardHome.tsx`, `src/components/dashboard/views/OperationalView.tsx` และหน้าประชาชนที่ใช้ชุดข้อมูลเดียวกัน

ผลส่งมอบ: ตารางแหล่งข้อมูลที่ตรวจแล้ว บัญชีสถานีเสนอรับรอง และหน้าแสดงค่าพร้อมที่มา โดยไม่อ้างข้อมูลทั้งจังหวัดเป็นข้อมูลลุ่มน้ำ

### รอบที่ 2 หน้าแรก โครงข่ายสถานี และการนำทาง

ขอบเขต R05–R07, R09, R14, R17, R23 รวมทะเบียนสถานีและค่าตรวจวัด ปรับแผนที่/เรดาร์ เตรียมช่อง ENSO ย้ายประกาศ เพิ่มเมนูโครงข่าย และ URL ของหัวข้อที่ตกลงแล้ว

ไฟล์หลัก: `BasinMap.tsx`, `DashboardHome.tsx`, `DashboardShell.tsx`, `dashboard/nav.ts`, `dashboard/types.ts`, `dashboard/permissions.ts`, `src/app/` และ migration ทะเบียนสถานีที่จำเป็น

ผลส่งมอบ: สถานีสามกลุ่มแยกด้วยสีและรูปร่าง เปิดรายละเอียดได้ layer ไม่กลบจุด และลิงก์แต่ละหัวข้อเปิดตรงได้ตามสิทธิ์

### รอบที่ 3 เก็บประวัติและสถิติ

ขอบเขต R12–R13 ต่อยอดฐานข้อมูลเดิม เพิ่มการนำเข้าจากภายนอก การจับคู่รหัสสถานี งานตามเวลา การตรวจข้อมูลซ้ำ/ขาด และสถิติ 7 วัน

แยกหน้าที่ให้ชัด: การรับ webhook ของโครงการ การ poll API ภายนอก การเก็บฐานข้อมูล และการ refresh หน้าเว็บเป็นคนละส่วน การเก็บต่อเนื่องต้องทำได้แม้ไม่มีผู้เปิดเว็บ

ผลส่งมอบ: ประวัติที่สอบย้อนกลับได้ นโยบายเพิ่ม/ลดความถี่ที่ตั้งค่าได้ และผลสถิติที่แสดงความครบถ้วน ไม่บวกค่าฝนสะสม 24 ชั่วโมงหลายรอบซ้ำกัน

### รอบที่ 4 คาดการณ์ ภัยแล้ง และชั้นข้อมูลสถานการณ์

ขอบเขต R07 ส่วน ENSO, R10–R11, R15–R16 รับแบบจำลอง/ชุดข้อมูลจากเป้และจัน เชื่อม adapter แยกการตรวจวัดออกจากการคาดการณ์ และผูก GISTDA กับเวลาของเหตุการณ์

ไฟล์หลัก: `src/lib/forecast/adapters.ts`, `src/lib/situation/adapters.ts`, `OperationalView.tsx`, `DataWarehouseCategoryView.tsx`, `DashboardHome.tsx` และชุด API/ตารางใหม่เท่าที่จำเป็น

ผลส่งมอบ: ENSO SPI/SPEI ฝนคาดการณ์รายลุ่มน้ำ/รายจุด และความเสี่ยงหมู่บ้านพร้อมที่มา รอบข้อมูล และข้อจำกัด โดยเลือกชุดคาดการณ์ล่าสุดได้เมื่อเปลี่ยนปี

### รอบที่ 5 SOP อพยพ CCTV และทรัพยากร

ขอบเขต R08, R18–R21 เริ่มจากศูนย์และ SOP ที่ท้องถิ่นรับรอง แล้วเพิ่ม CCTV/ทรัพยากร ส่วนเวลาน้ำเดินทางทำหลังรับแบบจำลองและมีข้อมูลตรวจเทียบ

ไฟล์หลัก: `ShelterOpsView.tsx`, `EvacuationMapView.tsx`, `src/app/api/shelters/route.ts`, `src/app/api/evacuation-route/route.ts` และหน้า/API/ตารางสำหรับ SOP CCTV ทรัพยากร

ผลส่งมอบ: หมู่บ้านมีปลายทางอพยพที่ยืนยัน ทะเบียนศูนย์และทรัพยากรอัปเดตได้ SOP มีเจ้าของและเวอร์ชัน ส่วนเวลาน้ำมาถึงแสดงเฉพาะเมื่อแบบจำลองพร้อมใช้งานตามเกณฑ์ที่ตกลง

### รอบที่ 6 ตรวจรับร่วมกับเจ้าของข้อมูล

ตรวจเทียบค่าบนเว็บกับแหล่งจริงและตัวอย่างผลแบบจำลอง ตรวจแผนที่ ชั้นข้อมูล มือถือ สิทธิ์ และการเข้าลิงก์ตรง เก็บผลตรวจรับตามรหัส R01–R23 เปิดเฉพาะฟีเจอร์ที่ข้อมูลและเกณฑ์พร้อม

รอบที่ 1 เริ่มได้ทันทีด้วยการทำบัญชีและถอดค่าตัวอย่าง ส่วนงานที่รอข้อมูลสามารถเตรียมโครงสร้างและสัญญาข้อมูลได้ แต่ยังไม่แสดงผลสมมติเป็นข้อมูลจริง ไม่กำหนดวันส่งมอบตายตัวก่อนทราบวันรับข้อมูลและความพร้อมของแบบจำลอง

## โครงสร้างข้อมูลที่เสนอ

เป็นข้อเสนอสำหรับออกแบบร่วมกับทีม ไม่ใช่ schema ที่ตัดสินใจแล้ว

- ทะเบียนแหล่งข้อมูล: เจ้าของ ที่มา ขอบเขต หน่วย ความถี่ และสถานะการรับรอง
- ทะเบียนสถานีรวม: รหัสกลาง รหัสต้นทาง กลุ่มสถานี เครื่องมือ พิกัด ลุ่มน้ำ สถานะ และรหัสอุปกรณ์โครงการถ้ามี
- ประวัติการตรวจวัด: เวลาตรวจวัด เวลารับ ค่า หน่วย คุณภาพ และแหล่งต้นทาง ต่อยอด `sensor_readings` สำหรับข้อมูลโครงการ ส่วนสถานีภายนอกออกแบบ mapping โดยไม่บังคับฟิลด์ IoT ที่ไม่มี
- เกณฑ์เตือนภัย: สถานี/ตัวแปร หน่วย ระดับอ้างอิง เงื่อนไข เวอร์ชัน ผู้รับรอง และช่วงที่มีผล
- ผลคาดการณ์: รุ่นแบบจำลอง เวลาออกผล เวลาที่คาดการณ์ พื้นที่/จุด และข้อจำกัด
- ความเสี่ยงหมู่บ้าน: รหัสพื้นที่ ระดับความเสี่ยง ช่วงเวลา วิธีประเมิน และเจ้าของข้อมูล
- SOP ศูนย์ และแผนอพยพ: เวอร์ชันเอกสาร ผู้รับผิดชอบ หมู่บ้าน ปลายทาง และเวลายืนยัน
- ทรัพยากร: หน่วยงานเจ้าของ ที่ตั้งปัจจุบัน ศูนย์ที่ประจำ ประเภท จำนวน หน่วย และประวัติการจัดสรร โดยไม่ล็อกให้ผูกได้กับศูนย์เท่านั้น

## เกณฑ์ตรวจรับสำคัญ

1. ฝนสูงสุด 24/72 ชั่วโมงคำนวณจากสถานีในขอบเขตที่รับรอง แสดงชื่อ เวลา หน่วย และจัดการกรณีค่าสูงสุดเท่ากัน/ไม่มีข้อมูลได้
2. ข้อมูลจากสถานีนอกพื้นที่ไม่เข้ารวมสถิติลุ่มน้ำโดยไม่มีเหตุผลที่รับรอง และยังดูเป็นสถานีอ้างอิงแยกได้ถ้าจำเป็น
3. สถานะวิกฤตสอบย้อนกลับถึงเกณฑ์/รหัสต้นทางได้ ข้อมูล ม.รทก. ไม่ถูกเทียบกับเกณฑ์ความลึก ม. โดยไม่มีการแปลงที่ถูกต้อง
4. ไม่มีตัวเลขตัวอย่าง ข่าวเก่า หรือ polygon จำลองแสดงเป็นสถานการณ์ปัจจุบัน และไม่มีข้อมูลไม่ถูกเติมเป็นศูนย์
5. กลุ่มสถานีทั้งสามมีทั้งสีและรูปร่างแยกกัน ชั้นพื้นที่ไม่บังจุดหรือ popup และเปิดปิด layer ได้จริง
6. หน้าแรกแผนที่ซ้าย เรดาร์ด้านล่าง ENSO ขวาบนจอใหญ่ และอ่าน/ใช้งานได้บนมือถือ
7. สถิติ 7 วันตรวจเทียบกับข้อมูลดิบได้ นิยามช่วงวันตามเวลาไทย ตรวจค่าฝนสะสม/ค่ารายช่วงให้ถูกต้อง และแสดงช่วงข้อมูลขาด
8. งานเก็บประวัติทำงานโดยไม่ต้องเปิดหน้าเว็บ มีการป้องกันข้อมูลซ้ำ และพิสูจน์การเพิ่ม/ลดความถี่ได้ด้วยข้อมูลทดสอบ
9. ENSO SPI/SPEI และฝนคาดการณ์แสดงแหล่งข้อมูล รอบผล และขอบเขตที่ตรงกับข้อมูลจริง ไม่เปลี่ยนป้ายข้อมูลจังหวัดให้เป็นรายลุ่มน้ำ
10. GISTDA แสดงข้อมูลพื้นที่และเวลาที่สัมพันธ์กับเหตุการณ์ ถ้าไม่มีข้อมูลใช้ได้ต้องไม่มีพื้นที่น้ำท่วมสมมติหลงเหลือ
11. ข่าวสาธารณะมีที่มาและสถานะยืนยัน ผู้ไม่มีสิทธิ์แก้ไขประกาศ/ทะเบียนไม่ได้ และข้อมูลจากจันใช้นิยามผู้ใช้ประโยชน์ที่ตกลงแล้ว
12. ศูนย์อพยพและปลายทางหมู่บ้านผ่านการยืนยัน ความจุไม่ถูกอ้างเป็นจำนวนที่ว่าง และเวลาขับรถไม่ถูกใช้เป็นเวลาน้ำเดินทาง
13. SOP เป็นฉบับที่หน่วยงานรับรอง CCTV เปิดได้ตามสิทธิ์ และทรัพยากรแสดงเจ้าของกับที่ตั้งแยกกันได้
14. เมนูใหม่เปิดตรง รีเฟรช และย้อนกลับได้ตามข้อสรุป R17 โดยตรวจทั้งหน้าประชาชนและเจ้าหน้าที่
15. ตรวจ lint, type check, build และทดสอบเฉพาะกฎคำนวณ/สิทธิ์/เส้นทางข้อมูลที่เปลี่ยน พร้อมตรวจการใช้งานจริงบนเดสก์ท็อปและมือถือ

## ข้อเสนอสำหรับเริ่มงาน

เริ่มรอบที่ 1 ก่อน โดยทำบัญชีข้อมูล ถอดค่าตัวอย่าง ตรวจฝนสูงสุด/สถานะระดับน้ำ และจัดรายการสถานีให้เจ้าของข้อมูลรับรอง พร้อมขอข้อมูลจากเป้ อ.หญิง จัน และท้องถิ่น งานนี้จะทำให้หน้าแรกและเมนูใหม่ใช้ข้อมูลชุดเดียวกัน และลดการแก้ซ้ำเมื่อเชื่อมแบบจำลองภายหลัง
